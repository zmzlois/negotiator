# negotiator memory

## architecture decisions

## 2026-06-07 — Offline Unsiloed book ingestion
**What was decided:** negotiation books parsed by Unsiloed are converted offline into Moss `DocumentInfo` records through `Negotiator.Knowledge.Unsiloed` and a guarded Mix task. Raw parser chunks and deterministic retrieval cards can live in the same Moss index under different metadata `kind` values.
**Why:** runtime call state should keep using the existing `Negotiator.Retrieval` boundary, while book parsing, cleanup, and cloud index mutation stay outside the live call path.
**What was rejected:** do not make live call sessions read Unsiloed JSON files directly, and do not put parser OCR geometry or signed image URLs into Moss documents.

## 2026-06-06 — Persistent Silero turn authority
**Status:** superseded for the active phone flow on 2026-06-07. keep the native `SileroVad` modules available, but do not wire per-call `SileroVadSession` processes into `CallSession` until the basic Telnyx conversation loop is stable.
**What was decided:** Silero VAD is the only authority that commits audio end-of-turn in `silero_vad` mode. LLM work may run continuously and queue likely response candidates, but it must stay speculative until VAD emits a committed turn boundary. Replace per-request native VAD scoring with a persistent `SileroVadSession` per call participant so ONNX loads once, 20/32ms PCMU frames stream through one session, and the session emits `speech_started`, `candidate_pause`, `speech_resumed`, and `turn_committed`.
**Why:** Ultra-low-latency voice needs LLM/TTS preparation to happen ahead of time, but speaking must be gated by the acoustic endpoint so the agent does not interrupt a live human mid-turn. A persistent VAD session also avoids process spawn and ONNX session setup on every rolling-window score.
**What was rejected:** Do not let text partials, LLM turn-detection, or queued candidates fire voice playback in Silero mode. Do not keep using per-request native VAD scoring as the primary production path.

## 2026-06-07 — Simplified active phone turn boundary
**What was decided:** the active Telnyx phone flow uses final Telnyx transcription as the only turn-commit boundary for now. `CallSession` no longer starts per-participant `SileroVadSession` processes, no longer maintains rolling audio-turn windows, and no longer clears in-flight response jobs just because TTS is synthesizing. queued continuation prediction still runs from human investor partial/final speech, but LLM-generated simulated-investor lines do not start speculative queued-continuation jobs.
**Why:** the real call logs showed the app generating useful LLM/TTS work, then clearing or ignoring it before audio reached the caller. reducing endpointing to one obvious path makes the call loop debuggable: final transcript -> one provider job -> one voice output -> one Telnyx mark -> lifecycle done.
**Proof:** local dev sink proof emitted two PCMU outbound audio payloads and two acknowledged marks for the opening prompt plus idle follow-up, with only `:investor_reply_job_started` provider job events and no queued-continuation jobs. synchronous Moss indexing of the saved proof turn succeeded after transcript metadata was stringified.

- 2026-06-06: first milestone is cli-only fake media. `Mix.Tasks.Negotiator.Sim` starts a supervised `Negotiator.CallSession` through `Negotiator.CallSupervisor`.
- 2026-06-06: `Negotiator.CallSession` is the single source of truth for mode, transcript, candidate lines, briefing advice, and event log.
- 2026-06-06: agents depend on explicit `Negotiator.LLM` and `Negotiator.Retrieval` boundaries so moss, production llms, elevenlabs, and telnyx media routing can be wired without changing the call state machine.
- 2026-06-06: voice-ai scope requires first-class provider adapters, not fake-only simulation. the app is elixir-native with telnyx call control/media streaming, elevenlabs voice synthesis, minimax chat calls, and probabilistic turn detection.

## module boundary review

- 2026-06-06: supervision is simple and correct for the current milestone: `Negotiator.Application` starts `Negotiator.CallRegistry`, `Negotiator.CallSupervisor`, and optional Bandit HTTP. each live call is one `Negotiator.CallSession` process under a `DynamicSupervisor`.
- 2026-06-06: the main maintainability risk is `Negotiator.CallSession`. it owns state transitions, transcript writes, candidate prediction, audio buffering, transcription commits, cloned-voice output, event logging, and snapshot shaping. keep it as the call owner, but move helper responsibilities into focused modules before adding more features.
- 2026-06-06: telnyx webhook and telnyx media websocket normalize external events directly into `CallSession` calls/messages. that works, but the next orchestration improvement should keep provider adapters dumb behind an internal event boundary.
- 2026-06-06: agent modules are intentionally small, but they receive the whole call state and reach into providers directly. the next improvement should pass smaller input structs/maps into agents so provider access and prompt context are explicit.
- 2026-06-06: first refactor target is low-risk extraction from `CallSession`: event log/snapshot formatting and media audio helpers. avoid changing DTMF behavior, room orchestration, or provider selection in the same step.
- 2026-06-06: first module-boundary refactor kept `Negotiator.CallSession` as the single GenServer owner, but extracted helper responsibilities into `Negotiator.CallSession.Audio`, `EventLog`, `Modes`, `Snapshot`, `Speech`, and `Transcription`.
- 2026-06-06: keep future refactors in the same direction: provider adapters should normalize into internal call events, agents should receive explicit prompt input maps instead of the whole call state, and long-running provider calls should eventually leave the `CallSession` GenServer path.
- 2026-06-06: system prompts are centralized in `Negotiator.Prompts`. chat-completion tasks read prompts from that registry instead of embedding prompt strings in provider adapters.
- 2026-06-06: provider readiness should be checked through real app startup and call logs, not a separate harness.
- 2026-06-06: provider ingress now uses `Negotiator.CallEvent` as the internal event boundary. telnyx webhooks and telnyx media sockets normalize events before they reach `Negotiator.CallSession`; the older public helpers remain as compatibility wrappers.
- 2026-06-06: ellie-ai's useful pattern is live-call memory plus async provider work. `Negotiator.Memory` is now a supervised ets owner, keeps one live context per call, and copies that context into supervised provider tasks through `Negotiator.ProviderTaskSupervisor`, so llm, retrieval, turn detection, and voice synthesis do not block the call session process.
- 2026-06-06: prompt management stays centralized in `Negotiator.Prompts` for now. ellie-ai's db-backed prompt versioning is a good later step, but this app first needs one obvious prompt registry before adding persistence, active versions, or admin editing.
- 2026-06-06: dynamic response candidates are now first-class state. `Negotiator.ResponseQueue` ranks A-E candidate lines, stores the queue on snapshots and live memory, and the negotiator reply path speaks the best queued candidate when available before falling back to a direct negotiator llm completion.
- 2026-06-06: `Negotiator.CallSession.ProviderJobs` is the new boundary for long-running provider calls. `CallSession` still owns state transitions, but provider jobs send typed results back as messages, matching ellie-ai's lesson that the call process should coordinate response lifecycle instead of performing all external work inline.
- 2026-06-07: partial transcript updates enter the same partial-speech path as simulator partials and are used to refresh queued responses before the final transcript turn is committed.
- 2026-06-07: Telnyx outbound audio now includes the interrupt path. media socket still serializes PCMU bytes as `{"event":"media","media":{"payload":"..."}}`, and `CallSession` now sends `{"event":"clear"}` through the media socket when remote speech starts or the founder returns, preventing stale negotiator audio from continuing over the investor.
- 2026-06-07: Telnyx `mark` frames now close the voice playback loop. `CallSession.Audio.send_voice_output/3` sends phone-ready audio plus a role-specific `mark_audio` message, `MediaSocket` serializes it as `{"event":"mark","mark":{"name":"..."}}`, and returned mark events transition `ResponseLifecycle` to `:done`.
